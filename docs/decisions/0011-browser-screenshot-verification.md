# ADR 0011: Browser screenshot verification for UI changes

- Status: Accepted
- Date: 2026-07-31

## Context

Behavioral tests can prove that controls exist and work while missing obvious
visual defects such as collapsed spacing, unstyled native controls, overflow,
or broken responsive layouts. These regressions are especially easy for an
agent to overlook when it evaluates only source code and DOM assertions.

The project already uses Playwright, so it can render the production build in a
real browser without adding another testing system.

## Decision

Every pull request with a user-visible UI change must include browser-based
visual verification:

1. Render each affected screen and important interaction state with Playwright
   against the built application.
2. Verify at representative desktop and mobile viewports whenever the affected
   layout is responsive.
3. Capture screenshots with synthetic data, inspect the images, and attach the
   relevant before/after or final-state evidence to the pull request.
4. Add behavioral or layout regression assertions where practical. Screenshot
   evidence complements tests; it does not replace them.
5. Record any viewport or state that could not be verified and explain why in
   the pull request.

Screenshots may be generated by a focused Playwright test or an equivalent
Playwright script. They should contain no real receipt, merchant, email, or
other private data.

## Consequences

UI pull requests take a little longer and carry reviewable visual evidence.
Reviewers can judge the actual rendered result instead of inferring it from CSS,
and future agents have an explicit completion gate for visual work.

This is a manual review requirement rather than broad pixel-perfect snapshot
testing. It avoids brittle image baselines while still catching the class of
regression that DOM-only checks miss.
